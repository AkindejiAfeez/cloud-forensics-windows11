# Digital Forensics Investigation Framework for Cloud Storage on Windows 11

A practical digital forensics investigation framework for recovering and correlating OneDrive and Google Drive artefacts from Windows 11 endpoints across deletion, account sign-out, synchronisation and encrypted-storage scenarios.

## Project Overview

Cloud storage applications increasingly leave forensic artefacts on endpoint systems even when files have been deleted, synchronisation has been interrupted, or an account has been disconnected.

This project investigates the forensic value of artefacts generated by **Microsoft OneDrive** and **Google Drive** on a **Windows 11 25H2** endpoint.

The investigation combines:

* Windows Registry analysis
* Windows Event Log analysis
* Prefetch analysis
* SQLite database analysis
* Memory forensics
* Cross-source artefact correlation
* Controlled virtual-machine experimentation

The project also develops a **13-stage digital forensics investigation framework** designed to provide a structured workflow for investigating cloud-storage activity on Windows endpoints.

> **Research project:** MSc Cyber Security, University of Hertfordshire

---

## Research Questions

The investigation addressed the following questions:

1. What forensic artefacts are generated by OneDrive and Google Drive on Windows 11 endpoints?

2. Which artefacts remain available following file deletion or cloud-account disconnection?

3. What information can be recovered from Registry, Prefetch, Event Log, SQLite database and memory artefacts?

4. How can artefacts from different forensic sources be correlated to support an investigation?

5. How can the resulting investigation process be structured into a repeatable forensic framework?

## Investigation Scenarios

Four controlled scenarios were investigated.

### Scenario 1 — Active Cloud Synchronisation

The endpoint was configured with cloud-storage applications and active synchronisation.

The purpose was to identify baseline artefacts generated during normal cloud-storage activity.

### Scenario 2 — File Deletion

Files associated with cloud-storage activity were deleted.

The purpose was to determine whether relevant forensic artefacts remained available after deletion.

### Scenario 3 — Account Sign-out

Cloud-storage accounts were disconnected from the endpoint.

The purpose was to examine the persistence or removal of local cloud-client artefacts following account sign-out.

### Scenario 4 — Encrypted Storage

VeraCrypt was used in the controlled environment alongside cloud-storage activity.

The purpose was to examine whether evidence associated with encrypted-storage software could be identified through memory and cloud-client artefacts.

## Artefacts Examined

The investigation examined multiple evidence sources:

### Windows Registry

Registry artefacts were examined for evidence of:

* Cloud-account configuration
* OneDrive account information
* Sign-in information
* Application configuration
* Persistence following deletion or account disconnection

### Prefetch

Windows Prefetch artefacts were examined to identify execution evidence associated with relevant applications.

### Windows Event Logs

Windows Event Logs were examined for system and process activity relevant to the investigation.

### SQLite Databases

Cloud-client databases were examined for application-specific information.

Examples include OneDrive and Google Drive database structures containing file, synchronisation and metadata information.

### Memory

Memory analysis was used to investigate running processes, network information, command-line information and loaded modules.

Volatility 3 was used for memory analysis.

---

## Key Findings

The controlled experiments demonstrated that cloud-storage applications can leave recoverable forensic artefacts across multiple Windows evidence sources.

### OneDrive Registry Persistence

OneDrive-related Registry artefacts remained identifiable following tested deletion and account-disconnection activities.

The investigation identified OneDrive account-related information within the Windows Registry, demonstrating the value of Registry examination even when cloud-client database information had changed or become unavailable.

### OneDrive Database Artefacts

OneDrive database artefacts were examined for information associated with synchronisation and file activity.

Deletion-related information was identified within the tested OneDrive database artefacts.

### Google Drive Database Artefacts

Google Drive SQLite databases were examined for residual information following file-deletion activity.

The investigation identified MD5-related information within the tested `mirror_sqlite` database associated with deleted content.

### Account Sign-out

Following cloud-account disconnection, the tested cloud-client databases did not retain the same level of file-level information observed during active synchronisation.

However, Registry artefacts associated with OneDrive remained available in the tested environment.

This demonstrates the importance of examining multiple evidence sources rather than relying exclusively on application databases.

### Memory Evidence

Memory analysis identified evidence associated with VeraCrypt, including:

* `VeraCrypt.exe`
* `veracrypt.sys`

This demonstrated the value of volatile-memory examination when investigating encrypted-storage activity.

## 13-Stage Investigation Framework

The project developed the following investigation workflow:

1. Pre-acquisition documentation
2. Live RAM capture
3. Registry export
4. Artefact export
5. System shutdown
6. Registry analysis
7. Prefetch analysis
8. Event Log analysis
9. OneDrive database analysis
10. Google Drive database analysis
11. Memory analysis
12. Cross-source correlation
13. Evidence reporting

## Reproducibility

The investigation was performed using controlled Windows 11 virtual-machine scenarios.

The repository documents:

* Investigation methodology
* Acquisition and analysis workflow
* Forensic tools
* Relevant commands
* Artefact locations
* Scenario descriptions
* Analysis techniques
* Findings
* Investigation limitations

The repository is intended to provide sufficient methodological information for other researchers and practitioners to understand and reproduce the investigative approach in an appropriately controlled environment.

Raw forensic images, memory dumps, personal cloud data, credentials and other sensitive evidence are **not included** in this repository.

---

## Evidence Handling

The project follows a forensic approach based on preservation, documentation, acquisition, examination, analysis and reporting.

Where possible, evidence was analysed using copies or exported artefacts rather than modifying the original evidence source.

The investigation also considered the forensic principles used within the project methodology, including documentation and preservation of evidence.

---

## Limitations

The investigation was conducted within a controlled single-user virtual-machine environment.

The project has several limitations:

* The experimental environment represents a controlled endpoint rather than a production enterprise environment.
* Only selected cloud-storage platforms were examined.
* One memory-acquisition attempt was affected by an interruption within the virtual-machine environment.
* Full-disk forensic imaging could not be completed for every scenario.
* External practitioner validation was not conducted.
* The experiments did not cover every possible Windows 11 or cloud-client configuration.

Further work could extend the investigation to additional cloud platforms, physical endpoints, mobile devices, enterprise environments and practitioner validation.
